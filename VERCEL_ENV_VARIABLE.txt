  rendering (`@vis.gl/react-google-maps`), an interactive address search bar,
  and nearby-amenity markers within a radius of the searched address.
- Adds backend `/api/geocode` and `/api/places/nearby` endpoints — routed
  server-side rather than called directly from the browser, since Google's
  Geocoding/Places APIs reject referrer-restricted keys, and the browser-side
  Maps key needs referrer restriction.

not sign up. Will need another push at the nearest future. Woowee

## Environment variables required for this to work once deployed
New config needed for the map/geocoding feature and Google OAuth — nothing
else changes.

**Vercel (frontend project)**
- `VITE_GOOGLE_MAPS_API_KEY` — Maps JavaScript API key, HTTP-referrer-restricted
  to the production domain(s). Team credentials sheet.
- `VITE_API_BASE_URL` — the deployed backend's origin (Render URL). Also now
  required for geocode/places, not just auth/reports.
- `VITE_GOOGLE_OAUTH_CLIENT_ID` — the OAuth 2.0 Client ID (not a secret, but
  still tied to authorized origins — see below). Same value as the backend's
  `GOOGLE_OAUTH_CLIENT_ID`. Team credentials sheet.

**Render (backend service)**
- `GOOGLE_MAPS_SERVER_KEY` — a *separate* key from the Maps JS one above. Must
  NOT be referrer-restricted (Google rejects that for server-to-server
  Geocoding/Places calls) — restrict by IP instead, or leave unrestricted.
  Team credentials sheet.

> Before this works in prod, add the Vercel production URL (and any preview
> domains you want it to work on) to that OAuth Client ID's **Authorized
> JavaScript origins** in Google Cloud Console — Google's button silently
> fails to issue a credential from an unlisted origin.
